# 图书馆双镜面、光丝散射与窗光实施方案

> 历史实施记录（2026-10-03 收尾标记）：下文保留当时的方案和验证，不是当前待办。现役功能、素材和启动方法以 [README](../../../README.md) 为准。

> 当前状态：用户随后要求去除两面镜子，已移除镜面及专用模块、依赖。保留长按光丝散射、增亮、窗光与此前通道效果。镜面测试中的散射检查迁移为 `tests/library-scatter.cjs`。下文是当时实施记录，镜面截图与验收数据属于历史版本。

目标：左右各一面镜子能看见同步运动、同步受光的宇航员；长按时光带分出细丝并变亮；窗光更清楚地斜射入通道。

用户已确认设计并要求直接实施。沿用当前检出与本地预览，不提交或上线。

## 实施步骤

1. 新增 `tests/library-mirrors.cjs`：先验证没有双镜面的旧版失败。浏览器内检查真实反射纹理中隐藏人物前后的像素差、左右倒影投影位置、长按和释放、暂停与手机布局。
2. 新增 `js/library-mirrors.js`，使用与现有 Three.js 相同版本的官方 Reflector，存入本地 vendor。两面镜子每帧各反射一次，反射时隐藏彼此；背景与人物分别使用现有光源渲染，保留深度遮挡。镜面倾斜角度保证默认画面能看见倒影，手机降低反射分辨率。
3. 修改 `js/library-space.js`：保留主光带，新增低数量的实例化分叉光丝，使用现有加速值连续控制展开幅度、透明度和亮度。顶点变形包围盒包含最大散射范围，防止循环跳变。
4. 修改 `js/library-daylight.js`：提高窗光雾束可见度、调整渐淡曲线，保持实际光源和可见光束同向，避免整屏泛白。
5. 在 `js/library.js` 接入镜面更新与加速控制。检查桌面、手机截图及完整循环；运行镜面、远端边界、几何回收、窗光、原有交互测试。

## 验收标准

- 两面反射纹理中均有真实宇航员像素；默认视角倒影处于屏幕内，实际镜面裁剪区域内。
- 镜中人物受书架遮挡，镜面不产生递归反射。
- 长按时散射和亮度平滑增加，松开回落，暂停后所有动画冻结。
- 窗光可见地进入通道，镜面、书籍和人物细节仍可辨认。
- 不回退远处可视距离与循环衔接修复；浏览器无脚本或着色器错误。
- 在本机浏览器测量帧耗时并记录；性能有问题优先降低反射分辨率。

## 完成与验证

- 左右镜面采用固定倾角，桌面与手机分别调整宽度和位置，给中央通道留出视线。反射纹理宽度桌面不超过 768、手机不超过 384，使用最多 2 倍多重采样。
- 使用 [Three.js r169 官方 Reflector](https://github.com/mrdoob/three.js/blob/r169/examples/jsm/objects/Reflector.js)，文件原样存入本地 vendor，许可由已有 `LICENSE-three.txt` 覆盖。项目模块负责双场景绘制及避免镜面递归。
- 保留 1800 条主光带，新增 450 条可展开的细光丝；最大展开范围计入剔除与循环回收包围盒。光带强度从 0.30 随加速平滑增至 0.64。
- 窗光雾束强度从 0.085 调至 0.18，沿长度衰减更缓，保留象牙白窗光及冷白主光带的区分。
- 新测试先在旧版以“缺少左右镜面”失败。完成后反射纹理均检测到人物像素；主画面左右分别检测到 314、159 个可见人物像素，放入完整挡板后均为 0。展开光丝带来 1119 个可见变化像素。具体数值随捕获时刻略有变化。
- `library-mirrors.cjs`、`library-browser.cjs`、`library-depth.cjs`、`library-light.cjs`、`library-horizon.cjs` 均通过；运动及项目结构共 7 项测试通过。包括桌面、手机模拟、触摸、空格、暂停、32 秒完整加速循环及光源同步。
- 最终远端边界检查 64000 像素最大差异 0。连续长按捕获 934 帧，中位帧间隔 6.9ms、P95 7.1ms，覆盖 4 次段落接入。这是本机无头 Edge 的结果，不代表所有访客设备帧率。
- 结果与截图位于 `artifacts/library/mirror-checks.json`、`horizon-checks.json`、`mirrors-desktop.png`、`mirrors-boost.png`、`mirrors-mobile.png`。本地 HTTP 预览地址为 `http://127.0.0.1:4173/library.html`。
